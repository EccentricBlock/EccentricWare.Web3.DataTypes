# ABI conformance matrix

Traceability from `docs/specs/ABI_DATA_Design_Specs.md` (v2.1) section 15 (and sections 10, 11.3, 14) to the tests and evidence in this repository, with every gap listed. Tests are in `Eccentricware.Web3.DataTypes.Test/ABI/` (class names below; namespace `EccentricWare.Web3.DataTypes.Tests.ABI`). "Independent" means expected bytes or values come from Foundry `cast` 1.9.0, the Solidity documentation, Nethereum.ABI 7.1.0 or the test-local reference model (`ABIReferenceModel.cs`, `ABIIndependentEncoder.cs`), never from the code under test (`ABIFixtures.cs` quotes the `cast` command per fixture).

Evidence is code and test names, not a claim of completeness: what was **not** run or not covered is in "What is not covered" at the end and in `docs/abi-performance.md`.

## What is not covered

- **Architectures and platforms.** Only Linux x64 (.NET 10.0.15, JIT) was run, in Release and (for `Tests.ABI`) Debug. ARM64, Windows and macOS are untested here; `.github/workflows/ci.yml` runs the whole test project on all four but has not executed on GitHub. The allocation tests are the ones most likely to behave differently elsewhere.
- **Guard-page over-read tests run on Linux only** (`ABIWordRunGuardPageTests`, mmap and mprotect through libc; inconclusive elsewhere), and the vector kernels were not run on ARM64. Since 2026-11-19 the codec has no unchecked memory reads (the run kernels load bounds-checked slices, `docs/abi-design-notes.md` row 85), so an over-read on those platforms would throw rather than read out of bounds.
- **Coverage-guided fuzzing.** No fuzzer (SharpFuzz, AFL++, libFuzzer) was available; the seeds are generated in memory and the only randomised coverage is the seeded generative tests. No fuzzer-found input exists (the corpus folder is empty).
- **Solidity harness differential.** Expected bytes come from `cast` (Foundry's encoder), the Solidity documentation and Nethereum.ABI; no contract was compiled and called, and `eth-abi` was not installed.
- **Performance gates.** A BenchmarkDotNet short job (3 iterations, in-process) only: wide error bars, no accepted baseline, no 10% regression gate, no full-policy p50/p95/p99 latency, no peak-process-memory or stack measurement. `docs/abi-performance.md` states every number with that caveat.
- **Finite harness timeouts (spec 10.4).** Every CI `dotnet test` step runs with `--blame-hang-timeout 10m` (a test that hangs for 10 minutes aborts the run with a hang dump; added 2026-11-19), inside the job's 30-minute limit; the fuzz targets also bound their own work (512 script events, oracle caps). No per-test `[Timeout]` is set. The CI workflow has not run on GitHub.
- **Stack and scratch usage bounded and measured (spec 14).** Bounded by construction (validator frames: 8 or 32 of 32 bytes; writer scratch: 52 bytes per open container; all caller-owned or on the stack), not measured at process level.
- **RLP-to-ABI fuzzing.** Seeded mutation tests of the adapter and the walker (`RLPCalldataAdapterTests.MutatedEnvelopes_*`, `NestedCallWalkerTests.MutatedNestedCalldata_*`), not a coverage-guided target.
- **Trimming and Native AOT.** The library declares `IsTrimmable` and `IsAotCompatible` as false (`EccentricWare.Web3.DataTypes.csproj`); no trim or AOT publish was run. The trim and AOT analyzers (`-p:IsAotCompatible=true`) report 0 warnings for the whole library, which is a static check only.
- **EVM adapters: scope limits.** `RLPCalldataAdapter`, `ContractFunctionResolver`, `ExecutionDescriptor` and `NestedCallWalker` ship in the core assembly (namespace `ABI.EvmAdapters`; spec 12 makes a separate assembly optional). Not provided: registry persistence or JSON ABI import, code and state acquisition (no RPC), secp256k1 recovery (sender and EIP-7702 authority: the host's), descriptor verification, chain-id policy, a policy over EIP-7702 delegations, a signer, and EIP-712 or initcode handling. The layouts were checked against Nethereum.Model and, on 2026-11-19, against the EIP-7702, EIP-4844 and EIP-2681 texts (read through a fetch tool that returns excerpts). EIP-7702 outcomes that depend on an authority's nonce or code are exact for the host's pinned state only (`docs/abi-design-notes.md` row 81). JSON ABI import, registry persistence and RPC are out of scope for the core (spec 1.3, 12).
- **Mutation of the backing buffer.** Not detected by the codec (spec 3.2); tested only as memory safety plus the digest-binding pattern.
- **Unreachable defensive branches.** The validator's frame-capacity guard and its container-completion checks cannot be reached with a valid compiled schema and are untested by construction (`docs/abi-design-notes.md` row 35).
- **An unexplained runtime crash.** `docs/abi-design-notes.md` rows 38 and 52 record an intermittent "Internal CLR error" seen once in a reviewer's multi-threaded harness; it was not reproduced since (row 52 has the counts).
