# ABI design notes

Running list of decisions where the specification (`docs/specs/ABI_DATA_Design_Specs.md`, v2.1) is silent, ambiguous or
self-contradictory. Later work appends rows. Columns: decision, spec section, reason.

## Foundation (schema, limits, selectors)

| # | Decision | Spec | Reason |
|---|---|---|---|
| 1 | Namespace `EccentricWare.Web3.DataTypes.ABI`, folder `ABI/` (not `Evm.Abi`). | 5, 12 | Repo convention, set by the shared brief. |
| 2 | Compile-time depth uses the decoder convention: root tuple = 1, every nested tuple, array, array element or primitive adds one. `ABICompileLimits.MaxSchemaDepth` is valid in `[1, 32]` (hard cap `HardMaxSchemaDepth`). | 4.1, 6.3, 6.4 | The spec gives the runtime depth rule and a 32-frame stack but no compile rule; a schema deeper than 32 can never be decoded, and the cap also bounds compiler recursion. A leaf under a depth-31 container chain therefore sits at depth 32. |
| 3 | Defaults the spec does not state: `MaxFixedArrayElements` 4,096 (the decoder array default), `MaxTupleElements` 1,024, `MaxStaticEncodedBytes` 262,144 (the decoder byte default). `MaxSchemaNodes` 4,096 and `MaxSchemaDepth` 32 are the spec values. | 6.4 | Chosen above any real struct (tens of members) so real traffic is never rejected; every field is configurable. A static array above 4,096 elements (for example `bytes32[8192]`) is rejected by the defaults and needs a larger `MaxFixedArrayElements`. |
| 4 | `MaxStaticEncodedBytes` is applied to every tuple and fixed-array HEAD region (for static ones that is the whole encoded size; for dynamic ones it is the pointer/inline head). The check is made on the running head sum while the members are added, so the failing path names the TUPLE (or array) whose head region crosses the limit, not the member that tipped it over. | 4.1 "static footprint bounds" | A dynamic tuple with a huge inline static member has the same head-size problem as a static one. |
| 5 | Compile failures map to statuses: invalid limits / null arguments -> `InvalidArgument`; grammar, widths, scales, cycles, negative length -> `InvalidSchema`; `T[0]` -> `UnsupportedSchema`; arithmetic overflow -> `ArithmeticOverflow`; depth -> `DepthLimitExceeded`; node count, tuple arity, fixed-array length, static footprint -> `ElementLimitExceeded`. A precise `ABISchemaErrorReason` rides along. | 4.1, 5 | The spec lists the statuses but not the mapping. Reasons make tests exact without inventing statuses. |
| 6 | Overflow is checked before the static-size limit: a head size above `int.MaxValue` reports `ArithmeticOverflow`; one within `int` but over the limit reports the limit. Sizes are computed in `long` and narrowed only after both checks. | 2.2, 4.1 | Deterministic ordering; no unchecked wrap, so the checked-arithmetic build cannot throw. |
| 7 | `ABITupleDefinition` is a mutable builder (`Add`); `ABITypeDefinition` is immutable and refers to builders for tuples. Cycles are only possible through a builder, and the compiler detects them by reference identity along the current path (reported before any budget). The compiler copies everything, so later mutation is harmless. Definitions are not thread-safe while compiling. | 4.1, 4.3 | The spec allows "immutable descriptors or defensive-copy builder inputs" and requires cycle rejection; a fully immutable graph cannot contain a cycle. |
| 8 | No parameter names are modelled, so "duplicate/conflicting parameter definitions" is vacuous. | 4.1 | Names are excluded from signatures and from the encoding. |
| 9 | No subtree sharing in the node table: every type occurrence gets its own node. A definition DAG expands, and node count and static size stop an exponential expansion. Consumers must not assume a node has a unique parent. | 4.1 (MAY) | Reuse is optional; skipping it keeps ids, `NextDynamicSibling` and the reverse pass trivially correct. |
| 10 | Node ids are pre-order: root is 0 and every child id is larger than its parent's. `StaticSize` of a dynamic node is `-1` (`ABISchema.NotStatic`), not 0, so a misused value is visible. `HeadSize` of a dynamic array is 0 (count * `ElementHeadWidth` at run time). | 4.1, 5.3 | Documented in the header of `Schema/ABISchema.cs`; the decoder, locator and writer program against it. |
| 11 | `NextDynamicSibling` is a tuple POSITION (not a node id), defined for every position (static ones too), `-1` when none. The offset word of that sibling is at `headBase + children[next].HeadOffset`. For homogeneous arrays the spec's `index + 1` rule is left to the locator (no table entry per element). | 4.1, 5.3 | Matches "next dynamic sibling (or a sentinel) for every child position". |
| 12 | The text parser is strictly canonical: no whitespace, no parameter names, no `tuple` keyword, no leading zeros in numbers, ASCII digits only. It is purely syntactic (so `uint7`, `bytes33`, `T[0]` parse); every width, scale, length and limit rule lives in the compiler only. Array length digits above `int.MaxValue` -> `ArithmeticOverflow`. Tuple nesting in text is capped at 32 and array suffixes are parsed iteratively. | 2.1, 4.1 | Only canonical text may reach the Keccak hash; one place for each semantic rule. |
| 13 | `TryCompile*` out parameters are `[NotNullWhen(true)] ... ?` instead of non-nullable. Added convenience `TryCompileFunctionSignature(string, in limits, ...)` (bootstrap, allocates). | 4.3 | Honest nullability contract on failure (mechanical, same behaviour). Name differs from the spec overload on purpose. |
| 14 | `ABISelector` is internal; a selector is obtainable only from an `ABIFunctionSchema` (no public constructor). Function names must be ASCII Solidity identifiers (`[A-Za-z_$][A-Za-z0-9_$]*`). `ABISchema.CanonicalType` and `ABIFunctionSchema.CanonicalSignature` are built from the compiled nodes, never copied from input. | 4.1, 4.3 | A caller-supplied selector or non-canonical text must not be able to disagree with the hashed signature. |
| 15 | Decode/encode limits accept `MaxEncodedBytes` up to `int.MaxValue` (no extra cap). The decoder must therefore use subtraction-based containment everywhere (`length <= size - offset`) and never compute `offset + length` unchecked. | 5.1, 6.1 | The spec only requires positive limits. |
| 16 | Test filter caveat: `--filter "FullyQualifiedName~ABI"` is case-insensitive and also matches the existing Address test `Parse_Unprefixed40HexWithoutZero_FamilyMatchesABigIntegerBase58Oracle_...`. That test fails in the checked-arithmetic build because `Address.TryParseBare40Chars` (Address.cs:443) is not checked-clean; it is unrelated to ABI. Use `~Tests.ABI` for an ABI-only checked run. | Brief | Pre-existing; not changed here. |
| 17 | `ABIEncodeLimits.Default` equals the decode defaults (262,144 bytes, depth 16, 4,096 array elements) with `MaxWrittenValues` 16,384 and `MaxWorkUnits` 100,000. | 6.4, 7.1 | The spec states decode defaults only and says a signing pipeline SHOULD use matching maximum payload sizes. |

## Decoder (word rules, validator, locator, views)

Statuses below are the most specific member of `ABIStatus` for the situation. "Offset" is `ABIError.DocumentOffset`.

| # | Decision | Spec | Reason |
|---|---|---|---|
| 18 | Pointer statuses. `InvalidOffset`: the pointer is not a plausible in-document tail pointer (256-bit value above `int.MaxValue`, beyond the document, not 32-byte aligned, or below the end of its own head region). `NonCanonicalLayout`: a plausible pointer that is not the next canonical tail (gap, overlap, alias, duplicate, reversal), and trailing data after the root. Check order: 256-bit fit, bounds, alignment, head overlap, canonical position. Offset = the pointer slot (trailing data: the canonical end). | 2.3, 5.2, 10.2 | The spec lists the failure kinds and the statuses but not the mapping. This keeps "malformed number" and "valid-looking but non-canonical" apart. |
| 19 | Count and length statuses. A dynamic-array count above `MaxArrayElements`, including any count that does not fit 31 bits (2^31, 2^255, 2^256-1), is `ElementLimitExceeded` (one 256-bit compare, then narrowing). A `bytes`/`string` length word larger than the bytes that follow it, or not a 31-bit number, is `Truncated`; so is a count whose head table (`count * ElementHeadWidth`, computed in `long`) does not fit the remaining input; so is a missing padding byte. `padded` is only derived after `length <= remaining - 32`, which implies the spec's `length <= int.MaxValue - 31`. | 2.4, 6.3, 10.2 | Matches the status documentation ("not fully contained" is `Truncated`). |
| 20 | `MaxArrayElements` applies to dynamic-array counts only, not to fixed-array lengths. Fixed lengths come from the trusted schema (bounded by `ABICompileLimits`) and are further bounded by the visited-value and work budgets. The `ABIDecodeLimits` doc comment was reworded accordingly (comment-only edit to a schema/limits file). | 6.3, 6.4 | 6.3 bounds "T[]" counts and says nothing for `T[k]`; a `uint256[5000]` parameter must not be rejected by an attacker-oriented limit. |
| 21 | Work accounting (exact numbers are pinned by `ABIDecodeLimitsTests`). One visited value and one work unit per value entered, including the root, zero-width values and primitives. One work unit per 32-byte word examined: a scalar word, a dynamic child's offset word (charged by the parent), a count word, a length word, and ONE unit for the partially used last word when padding bytes exist (none when the payload is a whole number of words). Payload data words are not examined and cost nothing, so a 256 KiB `bytes` costs 4-5 units. Tuple head words are charged when read, never twice. Exhausting the visited-value budget is reported as `WorkLimitExceeded` (the status documentation covers "visited-value or work budget"). Counters are compared before they are incremented (`used >= budget` fails), so they cannot wrap even with budgets of `int.MaxValue`. | 6.4 | The spec defines the units but not how partial words and offset words are counted. |
| 22 | Order inside one step. Value entry: depth, visited budget, work budget. Inside a word: containment, then the work charge, then reading and checking. So a depth error of a child precedes any error in that child's pointer, and a truncated word is reported even when the budget is also exhausted. | 5.2 | 5.2 fixes the order within a field but not between a limit and a structural check on the same word. |
| 23 | Depth: primitives and `bytes`/`string` count as a level (root tuple 1, a leaf directly under it 2), so `MaxValueDepth = 1` only admits a zero-argument root. Depth is structural: an empty array never enters its element node, so empty arrays nested k deep need `MaxValueDepth = k + 1` while the same arrays holding one leaf need `k + 2`. | 6.4 | Spec text. Real traffic check: a Seaport `fulfillOrder` needs depth 6 (test), far below the default 16. |
| 24 | Frame fields differ from the table in 6.2 without loss: `HeadSize` is stored as `HeadEnd` (`HeadBase + HeadSize`), `Depth` is the frame index plus one, `PendingChild` and `State` are implicit (a child is pending while a frame above exists; the loop is the state machine). The frame is eight `int`s (32 bytes), unmanaged (asserted). Capacity is 8 or 32 frames chosen from `min(MaxValueDepth, schema.MaxDepth)`; nesting can never exceed the schema's own depth. Frame push is guarded by a capacity check that the depth logic makes unreachable. | 6.1, 6.2 | Fewer fields, same information. |
| 25 | Failure offsets: the start of the word, region or padding byte that failed (for padding the exact first non-zero byte); 0 when the root head does not fit; the canonical end for trailing data; -1 for argument, size and selector errors. For `ABICallData` offsets are relative to the arguments (coordinate zero at call byte 4). `ABIError.SchemaNode` is the node being processed. | 5.2 | The spec leaves offset semantics open. |
| 26 | Public signatures. `limits` is `scoped in` on `TryDecodeComplete` and `TryDecode` (compiler requirement: otherwise the returned ref struct is tied to the lifetime of the caller's limits variable; `RLPData` does the same). Added overloads that also return `ABIError` (spec 5.2 asks for it "in diagnostic builds"; the spec 5 signatures are unchanged). Limits are read once each into locals, so a concurrently changed limits variable cannot split validation from frame sizing (stress test). | 5, 5.2 | Mechanical, documented in the XML docs. |
| 27 | Accessors. `TryGetArrayLength` serves fixed and dynamic arrays only (tuple arity is schema knowledge). `TryGetBytePayload` serves `bytes` and `string` (raw bytes, no UTF-8 claim). The strict text step is `TryGetStringUtf8Validated` (string only; `bytes` is `TypeMismatch`) and uses the BCL `System.Text.Unicode.Utf8.IsValid` (rejects overlongs, surrogates, code points above U+10FFFF and truncated sequences; accepts U+0000). `TryGetWord` serves exactly the eight elementary kinds. A path error always wins over a type mismatch. `TryGetUInt64`/`TryGetInt64` serve `UInt`/`Int` of any width and report `ValueOutOfRange` for a canonical value that does not fit; they never accept `UFixed`/`Fixed`. | 2.1, 5.1 | Spec text, made explicit. |
| 28 | Added `ABIData.TryCompareSigned256` next to the optional `TryCompareUnsigned256` (static, both return -1/0/1, `InvalidArgument` and 0 for a span that is not 32 bytes). | 5.1 | The spec says signed comparison "MUST compare signs correctly" if offered; offering only the unsigned one invites misuse for `int256`. |
| 29 | Locator. `TryLocate([])` returns head `(0, RootHeadSize)` and value `(0, length)`; for a static root those are equal. A static child's head and value ranges are both its inline encoding; a zero-width child has a `Length = 0` range at its head position. A dynamic child's end is the next dynamic sibling's tail start (tuples: `NextDynamicSibling`; arrays: the next slot) or the container's end; its start must lie at or after the container's head end, its end at or before the container's end, and its extent must be at least one word. Path elements into a dynamic array are bounded by the count word read from the document; into a fixed array by the schema. | 5.3, 8.1 | Spec algorithm, with the defensive checks listed. |
| 30 | Defensive statuses (document changed after validation, never reachable for a validated unchanged document): `Truncated` for a word that is not contained, `InvalidOffset` for an inconsistent pointer or bound or a count that is not 31 bits, `NonCanonicalLayout` for a `bytes` value whose padded length disagrees with its range. Covered by tests that corrupt the bytes under a valid view (also over every prefix) and require a status or an in-document range, never an exception. | 3.2, 5.3 | Spec requires "re-check before slicing". |
| 31 | The locator is generic over a step counter (`IABILocateCounter`); the public path uses a no-op struct that the JIT erases. Tests use a counting struct to prove the step count does not depend on sibling count, static members between dynamic ones, or descendant size (10.3). | 5.3, 10.3 | Deterministic proof instead of timing. |
| 32 | `ABICallData`: `IsValid` is `Arguments.IsValid` (a selector-only call has an empty but valid argument view, so validity cannot be "bytes present"). The shared validator re-checks limits and size on the arguments (a handful of comparisons; the bytes are validated once). `TryTranslateArgumentRange` is translation only: any in-bounds range translates. | 6.1, 3.3 | Spec text. |
| 33 | `NoInlining` on the validator: kept only on `RunShallow`/`RunDeep` so each frame buffer lives in its own method. An informal Stopwatch comparison (2M decodes, best of 7, x64 Linux, .NET 10, one machine; NOT BenchmarkDotNet) showed no difference beyond noise (about 3 %) between the current layout, `TryValidate` inlinable, and the tier methods inlinable (transfer args about 17-18 ns, mixed nested document about 128-131 ns, two-element `bytes[]` about 45-49 ns). The attribute is therefore a layout guarantee, not a speed claim. Real measurements belong to the benchmarks. | 11.1 | AGENTS.md / brief: decisions measured. |
| 34 | Test provenance. Expected bytes come from Foundry `cast` 1.9.0 (commands quoted per fixture in `ABIFixtures.cs`), cross-checked by hand against the byte listings in the Solidity ABI specification for `baz`, `bar`, `sam`, `f` and `g`; hand-derived words (empty tuples, fixed-point extrema, malformed documents) are built from named words in the tests. Real-chain shapes (ERC-20, Uniswap V3 `exactInputSingle`, Uniswap `multicall`, Seaport `fulfillOrder`) use real contract and token addresses and the real selectors, but the bytes are encoder output: no mined transaction was fetched (no network access was used). A test-local recursive reference model (types, canonical encoder, permissive decoder) shares no code with the library and drives the differential and mutation tests. | 10.1, 10.4 | Honest limits of the evidence. |
| 35 | Coverage not claimed. Two defensive branches in the validator cannot be reached with a valid compiled schema and are untested by construction: the frame-capacity guard, and the container-completion checks (`HeadCursor == HeadEnd`, static size equality). 10.4's external differential (a Solidity harness, Nethereum or `eth-abi`) is not run here; `eth_abi` is not installed, so the independent references are `cast` and the test-local model. The RLP-to-ABI adapter and the writer-dependent vectors (10.1 round trips, measurement) belong to the writer and hardening work; the 10.5 flow uses `RLPData` directly for the calldata extraction. | 10.4, 10.5 | Scope boundaries. |
| 36 | Strictness reminder for integrators: the decoder rejects layouts that Solidity's own decoder accepts (gaps, overlap, aliasing, trailing bytes, padding garbage, high-bit garbage). That is the specified compatibility policy; there is no permissive fallback. Default limits accept realistic large traffic (4000 `(address,uint256)` pairs, 4096 `bytes32` proof words, a 262,080-byte blob, a 100-child multicall; tested); larger batches need a larger `MaxEncodedBytes`/`MaxVisitedValues`, which is a deliberate call-site choice. | 2.3 | Compatibility policy. |
| 37 | Independent review (read-only agent, own recursive reference decoder/encoder written from the spec; public API only). Result: no functional defect. More than 25 million mutants (word overwrites, wrong-base pointers, bit flips, truncations, appends, shifts, swaps) gave 0 accept/reject disagreements in either direction; about 4 million accepted mutants had every location and accessor compared and matched; exact budget boundaries, 133,497 scalar boundary words, the call path, native 2 GiB documents, the checked-arithmetic build and zero-allocation loops were clean. Two documentation nits were fixed: the `ABIStatus.InvalidOffset`/`NonCanonicalLayout` comments (they contradicted note 18) and a warning on `ABIDecodeLimits.MaxVisitedValues` that zero-width values are bounded only by the visited and work budgets (with both near `int.MaxValue`, 64 bytes of `(()[])` cost about 14 s before `WorkLimitExceeded`; with the defaults microseconds). | 5.2, 6.4 | Review evidence. |
| 38 | Unresolved observation from the same review: the reviewer's multi-threaded differential harness (10 threads, deep schemas) died intermittently with "Fatal error. Internal CLR error (0x80131506)" in roughly 1 of 14 to 1 of 50 process launches, never twice for the same seed, never single-threaded, and not in a 60 s, 262-million-decode library-only stress; no crash with `DOTNET_TieredPGO=0`, `TieredCompilation=0`, `TC_OnStackReplacement=0` or `gcConcurrent=0` in 14 launches each (too few to be conclusive). The decoder source has no `unsafe`, `stackalloc`, `Unsafe` or `MemoryMarshal`; the only low-level construct is the compiler-generated `[InlineArray]`-to-`Span` conversion for the frame stack (the same pattern `RLPValidator` uses). The cause is not established (a harness, an environment under memory pressure, or a runtime defect are all possible). It is recorded here, not dismissed; the repo suite was re-run 60 times as a cheap cross-check (result in row 52). | 11 | Honest disclosure. |

## Encoder (writer, measurer, call encoder)

| # | Decision | Spec | Reason |
|---|---|---|---|
| 39 | One shared engine. `ABIWriter`, `ABIMeasurer` and `ABICallEncoder` are thin public wrappers over the internal ref struct `Internal/ABIEncoder.cs`; the measurer runs the same state machine with `writes` false (no destination, no overlap check, byte limit only). The public frame types `ABIWriteFrame` and `ABIMeasureFrame` each wrap one internal `ABIEncodeFrame` (thirteen `int`s, 52 bytes, unmanaged, asserted; eight cursor/layout fields per frame plus five writer-wide fields used in frame 0 only, see row 50) and the scratch span is reinterpreted once with `MemoryMarshal.Cast` (safe code). Frame fields are `internal`, not `private` (C# cannot share a private field with the engine); the public types expose nothing. | 7.1, 7.5, 7.6 | "Exactly the same schema event sequence and sizing rules": one implementation makes a measured/written disagreement impossible by construction, and the differential tests prove it. |
| 40 | Frames and scratch. `TryBegin` clears the frames it can ever use (`min(scratch length, MaxValueDepth)`, at most 32) and then assigns frame 0, so stale caller content is never visible and a caller cannot forge an in-progress frame; frames beyond the depth limit are not touched (no cost for a long scratch span). Every other frame is fully assigned when pushed and frames above the current depth are never read. `TryBegin` requires at least one frame (`InsufficientScratch`); a missing frame for a nested container fails that container's open with `InsufficientScratch` and faults the writer (the 10.3 negative test). `MaxValueDepth` frames always suffice (frame count = open containers including the root; a container at depth d needs frame d-1). A scratch span that overlaps the destination (reachable only through `MemoryMarshal.Cast`) is refused at `TryBegin` with `InvalidArgument`, not `SourceOverlapsDestination` (the scratch is not a source). | 7.1, 7.4, 10.3 | Spec 7.1: scratch "must be filled/initialised by `TryBegin`". |
| 41 | Status mapping, all of which the spec leaves open. A call that does not match the next schema slot: `TypeMismatch`. More values than a tuple arity, fixed length or announced dynamic count (also at the root): `ElementLimitExceeded` (the status text covers "tuple arity or element count"). Fewer values at `TryEndContainer` or `TryFinish`, or an unclosed container at finish: `IncompleteWrite`. `TryEndContainer` at the root, twice, or before anything opened: `InvalidWriterState` (the root is closed by `TryFinish`). A source of the wrong length (address and function address not 20, word not 32, `bytes<M>` not exactly M): `InvalidArgument`. A caller value that does not fit the declared width: `ValueOutOfRange` (the decoder's `InvalidScalar` is for stored words). Negative element count: `InvalidArgument`; above `MaxArrayElements`: `ElementLimitExceeded`. Exceeding `MaxEncodedBytes`: `InputTooLarge` (checked before the destination size, which is `InsufficientDestination`). `ArithmeticOverflow` is never returned: all sizes are computed in 64 bits and compared by subtraction against bounds that are already proven (test with a span that claims `int.MaxValue` bytes and is never read). | 5, 7.2, 7.4, 10.3 | Deterministic, documented, each pinned by a test. |
| 42 | Check order of one operation, all before any byte is written or any frame field changes: writer state, arity, expected kind, then depth, value budget, work budget (as the decoder), then for scalars the source length, the value range and the overlap; for `bytes`/`string` the capacity (limit, then destination), the overlap and, for a `string` slot (either method, row 80), the UTF-8 scan; for containers the scratch, the array limit (dynamic arrays) and the capacity of the head. Capacity precedes the UTF-8 scan so the scan is bounded by the caller's own buffer, and overlap precedes it so the scan never reads bytes the write could change. | 5.2, 7.2 | Spec 7.2 requires validation before mutation; the order makes it cheap and deterministic. |
| 43 | Budgets are charged exactly like the decoder (decode note 21): one value and one work unit per value entered, one work unit per scalar word, per pointer word, per count word, per length word and one for a partially used last padded word; depth: root tuple 1, each nested container or leaf one deeper; `MaxArrayElements` applies to dynamic-array counts only; counters are compared before they are incremented. A document written under `ABIEncodeLimits` L therefore decodes under the equal `ABIDecodeLimits`. Proof: for 150 random documents and five dimensions the smallest limit that lets the document through is the same number for the writer, the measurer and the decoder (750 comparisons), and the failure status at limit-1 is identical. | 6.4, 7.1 | "Enforce matching configured budgets"; a pipeline that encodes and decodes under one policy must not meet a limit on one side only. |
| 44 | Strings. `TryWriteBytes` writes exactly the bytes it is given into a `bytes` slot or a `string` slot (raw, no claim that they are text); `TryWriteStringUtf8` serves `string` slots only, after strict `Utf8.IsValid` (`InvalidUtf8`, before any write). Together they satisfy invariant 5: encode(decode(x)) is the identity for every canonical document, including a `string` whose on-chain bytes are not UTF-8 (proved over 300 random documents with random, mostly invalid, string content and over the malformed-UTF-8 fixture). Review history: the first implementation refused raw writes into string slots (a documented shortcut); the independent review rated that a spec deviation (7.7 invariant 5, 7.2 "a separate raw-bytes method"), and it was changed. | 7.2, 7.7 | The raw method is the spec's "separate raw-bytes method"; the validating method keeps the strict-validation guarantee for callers that mean text. Callers who must sign only text use `TryWriteStringUtf8`. Superseded on 2026-11-19 by row 80: `TryWriteBytes` now validates `string` slots too. |
| 45 | Exact source shapes: a `bytes<M>` source must be exactly M bytes (no implicit padding or truncation), addresses and function addresses exactly 20, words exactly 32. Integer methods never serve fixed-point slots and the scaled methods never serve integer slots. `TryWriteUInt64` into a slot of 64 bits or more is always in range; `TryWriteInt64` sign-extends. Words are range-checked with the decoder's own bit rules (`ABIWord`). | 7.2 | A wrong-length source is a caller bug that must not become a silently different value. |
| 46 | Overlap. A source must not overlap any byte of the caller's whole destination span (for a call encoder the whole call buffer, selector bytes included; the argument writer's own span is the tail). Zero-length sources never overlap. Adjacent but disjoint memory (for example the byte after the destination in the same array) is accepted. | 7.2 | Spec text; the call guard follows from "never part of any ABI offset" plus "overlap any portion of the destination". |
| 47 | Call encoder. `MaxEncodedBytes` below 4 fails with `InputTooLarge`; the argument writer gets `MaxEncodedBytes - 4` (0 is legal: a selector-only call); a destination below 4 bytes fails with `InsufficientDestination`. The selector is written only after every check passed (nothing is written on failure) and a later document failure voids the whole buffer: `TryFinish` reports 0 bytes. `callBytesWritten = 4 + arguments` cannot overflow because the arguments never exceed `MaxEncodedBytes - 4`. | 7.5 | Spec text, with the status choices made explicit. |
| 48 | Not offered, deliberately: a length-only `bytes` measuring overload (spec MAY; UTF-8 and the length both need the source) and typed convenience overloads over `uint256`/`int256`/`Address`/`Hash32` (the brief calls them optional and the spec signatures must stay exact). shortcut: callers pass 32-byte words and spans; add extension methods later if the policy layer needs them. `TryBegin` takes `scoped in ABIEncodeLimits` (same mechanical compiler requirement as the decoder, note 26). | 7.1, 7.5 | Simplicity; no ad hoc public surface. |
| 49 | Failure atomicity as implemented: a failing operation writes no byte and changes no frame field (budget counters may already have been charged, which is irrelevant because the writer is then faulted for good). Bytes written by earlier successful operations stay in the destination: after any failure the destination holds no valid document and `TryFinish` can never succeed. A completed writer is dead as well, so a document cannot be extended or finished twice. | 7.2, 7.4 | Spec text; verified by a checked replay that compares the destination before and after every event of thousands of corrupted scripts. |
| 50 | All writer-wide mutable state (state machine position, open-container count `Top`, value counter, work counter) lives in scratch frame 0 next to the cursors; the ref struct holds only configuration assigned once by `TryBegin`. A struct copy of a writer therefore shares every bit of mutable state with the original (it cannot exceed a budget the original would enforce, cannot hide a fault, cannot finish a second document), instead of diverging on the stack. `default(ABIWriter)` has an empty frame span and reads as `Invalid` without touching any frame. Frame 0 also carries an epoch: `TryBegin` increments it and each writer value remembers its own, so a stale writer value whose scratch was reused by a later `TryBegin` reads as `Invalid` (re-review finding N1: without it the stale value could write into its old destination and advance the new writer, which could then finish having written nothing). Cost: one extra memory read or write per counter instead of a register, and 52-byte frames. | 7.1, 7.4 | Found by the independent review (a copy passed by value to a helper bypassed `MaxWrittenValues` and the Faulted state); the doc-only "do not copy" rule of `RLPWriter` is not enough for a signing path. |
| 51 | Independent review of the encoder (read-only agent, own recursive reference encoder written from the spec, public API only, run on a private copy of the repo). Result: no functional defect.
